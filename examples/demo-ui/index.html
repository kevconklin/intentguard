What this proves, in one paragraph

A prompt injection can corrupt what an agent wants to do — it cannot expand what the agent is allowed to do. Permissions are fixed from the user's trusted request before any untrusted content is read (step 1). Each tool call is then checked against those frozen permissions by a pure, deterministic pipeline (step 2): an allowlist gate (unknown tools are refused), an argument-shape gate (types, enums, regex patterns, length limits declared per tool — violations are denied invalid_arguments before the policy store is even consulted), a resource-binding gate (a call that can't be bound to a concrete resource is denied missing_resource), and finally the intent check against the policy store. The ledger (step 3) is append-only: your security telemetry. Try the guided attempts in panel 2 — each one demonstrates a different outcome.
