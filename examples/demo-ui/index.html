What this proves, in one paragraph

A prompt injection can corrupt what an agent wants to do — it cannot expand what the agent is allowed to do. Permissions are fixed from the user's trusted request before any untrusted content is read (step 1). Each tool call is then checked against those frozen permissions by a pure, deterministic pipeline (step 2): an allowlist gate (unknown tools are refused), an argument-shape gate (types, enums, regex patterns, length limits declared per tool — violations are denied invalid_arguments before the policy store is even consulted), a resource-binding gate (a call that can't be bound to a concrete resource is denied missing_resource), and finally the intent check against the policy store. The Ledger is append-only: your security telemetry. The Parser lab tests the one LLM in the system — the trusted-path intent parser — against labeled attack cases.

Parser lab

Each case shows the request, what the parser should grant, and what it must never grant (injected recipients, URLs, and paths hidden in pasted content).
