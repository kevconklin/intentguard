How this demo works

IntentGuard decides, per tool call, whether an AI agent's action is inside what the user actually asked for. A prompt injection can change what the agent wants to do — never what it is allowed to do.
  1. Provision intent (trusted, once). In panel 1, declare which tool → resource pairs the user's request authorizes, then click Provision session. In a real deployment this comes from parsing the user's request — before any untrusted content is read.
  2. Attempt tool calls (untrusted, per call). In panel 2, pick a tool and edit its arguments as JSON — or click a one-click scenario. Each call runs through the decision pipeline shown with the verdict: three deterministic gates (allowlist → argument shape → resource binding) and then the intent check against the policy store. No LLM is consulted; every deny fails closed.
  3. Read the audit log. Panel 3 shows every decision, append-only, with the machine-readable reason, the specific argument violation when there is one, and OWASP Agentic Top 10 threat tags. Flip observe/enforce (top right) to see observe mode allow everything while recording what enforce would have denied.
💡 New: argument-level validation. Each registry tool can declare per-argument shape constraints (type, enum, regex pattern, max length). A call violating one is denied invalid_arguments before the policy store is even consulted — the selected tool's constraints are shown in panel 2.
